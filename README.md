# inference

source for redqueen's inference runtime. the checkout on redqueen is `/srv/ai/inference`.

`hosts/redqueen` tracks host-owned code, configuration, pinned versions, model metadata and integrity manifests, and the ComfyUI workflows used by the deployment. run `hosts/redqueen/link-runtime.sh` as `ai` to make live user-owned host paths symlinks into this checkout and reload user units; it does not restart services. root-owned firewall files can be linked separately with `sudo hosts/redqueen/link-system-runtime.sh`.

- `hosts/redqueen/adapters/` provides the System One/Decisions and OpenAI-compatible image adapters.
- `hosts/redqueen/model-router/` contains llama-swap configuration, runtime helpers, and pinned build metadata.
- `hosts/redqueen/comfyui/` tracks ComfyUI configuration, dependency pins, and workflow assets. the upstream ComfyUI checkout, virtual environment, and user state are separate host data.
- `hosts/redqueen/models/` contains download scripts, version/checksum metadata, and the non-weight model metadata linked from `/srv/ai/models`.
- `hosts/redqueen/systemd/` contains user service units. `systemd-system/` and `nftables.d/` contain root-owned firewall configuration.
- `hosts/redqueen/archive/` contains the encrypted backup setup.
- `hosts/redqueen/tests/` contains host-side verification and stress scripts.

Downloaded model weights, credentials, the private archive environment, virtual environments, caches, generated input/output, and compiled upstream binaries stay on the host. historical rollback snapshots stay local.

the memory scheduler owns port `8081`; llama-swap listens privately on `127.0.0.1:8084`. it reserves weights, configured context/KV cache and compute memory using llama.cpp's allocation-free planner, plus headroom, against both host RAM and the GPU's shared memory pool. versioned worker profiles bind weights to tracked revisions and checksum manifests, declare supported request shapes and concurrency limits, and split admission memory into mandatory, reclaimable, and transient peak components. existing fixed-size workers have no reclaimable allocation until their runtime can release it and report the backing returned. idle backends are evicted in least-recently-requested order; active requests hold leases through completion. a shared file-backed execution lease serializes admitted chat, decision, and image work across the broker and adapters. the public model gateway admits at most four requests at a time; excess requests receive `429`, while capacity conflicts return `503` with `Retry-After: 1`. image and decision adapters stay listening while their backends are unloaded. the legacy GLM/ComfyUI pause helper is disabled; scheduling now coordinates all backends.

OpenAI-compatible service workers can declare a loopback `gateway_url`, local `health_url`, and `/slots` probe returning llama.cpp-compatible entries with boolean `is_processing` fields. their profiles also declare supported request shapes, including separate text and image inputs. the public gateway routes those workers directly only after scheduler admission; workers without `gateway_url` continue through llama-swap.

deploy as `ai` from the clean `/srv/ai/inference` checkout tracking `origin/develop`: `bash hosts/redqueen/model-router/deploy-scheduler.sh --update`. this drains existing work before pulling, journals the prior revision/profiles/unit flags durably before any source update, and serializes update, activation and automatic recovery with `/srv/ai/model-router/run/operations.lock`. active work that cannot drain within 60 seconds is left running and the source is not updated. the deploy command verifies the Python 3.13 venv pins, rebuilds memory profiles, validates units/config, relinks the existing runtime paths and restarts the API services. activation failure restores the prior source revision, profiles, unit enablement and active services; rollback leaves the checkout detached at the saved revision. `--rollback-ref "$previous"` remains available for an already updated checkout, but cannot protect the earlier manual pull. use `--check` alone to validate/profile without restarting services or updating source. rebuild profiles whenever weights, runtime binaries, context settings or scheduler policy change; stale profiles fail closed.

the scheduler, memory profiler and deployment tooling use the dedicated model-router venv. image/decision adapters use `/srv/ai/adapters/venv`; ComfyUI and CLM retain their own venvs. llama.cpp runtimes are compiled binaries isolated by their versioned directories and pinned ROCm library paths.

deployment reuses an existing model-router venv only when its dependency pins match; changed pins require a separately built replacement so failed deployments cannot silently change live dependencies. the first migration from the old adapters needs a quiet maintenance window because those processes do not hold scheduler leases.

install the uncensored image runtime once with `bash hosts/redqueen/comfyui/install-qwen-image-gguf.sh`; it installs the pinned custom node and GGUF dependency in ComfyUI's venv. deployment drains and stops resident backends so updated unit settings and plugins take effect on the next lazy start. image admission verifies the required workflow nodes are registered.

front services use continuous systemd restart attempts with a 5 to 60 second backoff, without exhausting start limits. `redqueen-supervisor.service` independently probes liveness every 15 seconds and checks recovery after three failures; downstream readiness failures do not trigger front restarts. recovery waits while inference leases are held and never expires work based on age. pending systemd recovery jobs retain a durable `maintenance.json` marker that blocks new admissions until the job completes and its front is healthy or definitely stopped; killing a control client does not cancel its systemd job. `redqueen-preflight.service` restores interrupted deployments at boot, recreates transient directories, and validates lingering, enabled fronts, credential names/private permissions, memory profiles and runtime dependencies. `/srv/ai/model-router/run/{boot-status,supervisor,recovery}.json` contain actionable local diagnostics. user lingering must be enabled once with `sudo loginctl enable-linger ai`; no login is required after reboot.

the recovery helper is a regular, atomically installed copy at `/srv/ai/model-router/libexec/host_reliability.py`, outside the mutable checkout and independent of application dependencies. the linker only bootstraps it; successful activation promotes the checked candidate. a failed or interrupted rollback retains its journal for retry and operator diagnosis. the helper never reboots the machine.

the router uses upstream llama-swap v260 at `fcefa7b7bebc326790937bbebc32ae87a958747c` with the tracked `llama-swap-v260-unbounded-load.patch`. upstream clamps `healthCheckTimeout: 0` to 15 seconds; the patch makes zero disable the model-load deadline while retaining bounded health probes and shutdown. install the versioned runtime before activating these units with `bash hosts/redqueen/model-router/install-llama-swap-runtime.sh [verified-prebuilt-directory]`; the source build requires Go 1.27.1. existing runtime binaries are preserved.
